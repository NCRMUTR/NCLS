## สิ่งที่ทำได้ในเวอร์ชันนี้

| ส่วน | รายละเอียด |
|---|---|
| ล็อกอิน | Google Sign-In · server ตรวจ ID token กับ Google (aud/iss/exp/email_verified) และ **ตรวจโดเมน `hd` ที่ server** · ออก token ของระบบเอง อายุ 8 ชม. |
| ผู้ใช้/สิทธิ์ | admin เพิ่มอีเมลอาจารย์ กำหนดระบบ `att` / `exam` / `asg` · ปิดใช้งานได้ · **ต้องมี admin ที่ใช้งานอยู่ ≥ 1 คนเสมอ** |
| ภาคเรียน | เพิ่ม/ตั้งภาคเรียนปัจจุบัน (เก็บ ค.ศ. แสดง พ.ศ.) |

| ความปลอดภัยพื้นฐาน | token ลงลายเซ็น HMAC · คำสั่งเขียนกันซ้ำด้วย `opId` · lock กันเขียนชนกัน · บันทึก AuditLog · ไม่มีรหัสผ่านใดๆ |

| ส่วน | รายละเอียด |
|---|---|
| เปิดคาบ | อาจารย์กด “ใช้ตำแหน่งปัจจุบัน” (GPS จากมือถือ/คอม) + รัศมี + เวลา “ปกติ/ปิดรับ” (เว้นว่าง = ค่าเริ่มต้นจากหน้าตั้งค่า) · เปิดได้ทีละ 1 คาบต่อวิชา · หน้าสดมี **QR + ลิงก์** (แสดงเต็มจอได้) |
| สถานะ | ปกติ 1 · สาย 0.5 · ลา 1 · ขาด 0 — **เฟสเวลาคำนวณที่ server เท่านั้น** · พักคาบ = เวลาหยุดเดิน และไม่ปิดเอง · ต่อแล้วเส้นตายเลื่อนตามเวลาที่พัก · คาบเลยเวลาปิดเอง |

## ขั้นตอนติดตั้ง (ทำครั้งเดียว ~20 นาที)

### A) สร้าง OAuth Client ID (Google Cloud Console)

1. เข้า <https://console.cloud.google.com> → สร้างโปรเจกต์ใหม่ (หรือใช้ของเดิม)
2. **APIs & Services → OAuth consent screen**
   - ถ้าบัญชีมหาวิทยาลัยเป็น Google Workspace และสร้างโปรเจกต์ใต้องค์กร → เลือก **Internal** (จำกัดเฉพาะบัญชีองค์กร ไม่ต้องรอตรวจสอบแอป)
   - ถ้าเลือกไม่ได้ → External แล้วเพิ่มอีเมลอาจารย์เป็น Test users (สถานะ Testing ใช้ได้โดยไม่ต้องส่งตรวจสอบ แต่จำกัด 100 บัญชี)
   - ขอเฉพาะ scope พื้นฐาน (`openid`, `email`, `profile`) ไม่ต้องเพิ่มอะไร
3. **Credentials → Create credentials → OAuth client ID → Web application**
   - **Authorized JavaScript origins**: ใส่ origin ของเว็บ เช่น `https://ชื่อผู้ใช้.github.io` (**ไม่ใส่ path** ไม่มี `/` ท้าย)
   - ไม่ต้องใส่ Redirect URI
4. คัดลอก **Client ID** (หน้าตา `1234-abc.apps.googleusercontent.com`) — ไม่ใช่ความลับ

### B) ติดตั้ง Apps Script

1. <https://script.google.com> → New project (ตั้งชื่อ เช่น `HBT Core`)
2. Project Settings → ติ๊ก **Show "appsscript.json" manifest file in editor**
3. สร้างไฟล์ให้ครบตามโฟลเดอร์ `gas/` (ชื่อเดียวกัน): `Config, Util, Db, Auth, Users, Settings, Courses, Students, Pin, Scores, Attendance, Assignments, ExamLink, Reset, Router, Setup` (.gs) และแทนที่เนื้อหา `appsscript.json` (**มีการขอใช้ Drive advanced service สำหรับลบถาวร** — ดูข้อ 3b)
4. เปิด `Setup.gs` แก้ค่าในก้อน `SETUP`:
   ```js
   GOOGLE_CLIENT_ID: '1234-abc.apps.googleusercontent.com',
   DOMAIN: 'rmutr.ac.th',
   FIRST_ADMIN_EMAIL: 'ชื่อคุณ@rmutr.ac.th',
   FIRST_ADMIN_NAME: 'ชื่อที่จะแสดง',
   ```
3b. **Drive advanced service** (ใช้ลบไฟล์ถาวรตอนลบข้อมูลสิ้นภาคเรียน): `appsscript.json` ที่ให้มาประกาศ `enabledAdvancedServices` ไว้แล้ว → ในตัวแก้ไขเมนู **Services** ควรเห็น *Drive API (v3)* · ถ้ารัน/ลบแล้วขึ้น error เกี่ยวกับ Drive API ให้เปิด **Google Drive API** ใน Google Cloud project ที่ผูกกับสคริปต์ · ถ้าเปิดไม่ได้ ระบบทำงานต่อโดยทิ้งไฟล์ลงถังขยะ (และแจ้งในหน้าลบ)
5. เลือกฟังก์ชัน **`setupCore`** → Run → อนุญาตสิทธิ์ (Sheets + **Drive** + เรียกบริการภายนอก — Drive ใช้เก็บไฟล์งานนักศึกษา)  
   ดู *Execution log*: ต้องเห็นบรรทัด "สร้างชีตใหม่", "สร้าง SEC_TOKEN", "สร้าง SEC_PIN", "ผู้ดูแล: …"  
   แล้วรัน **`setupCheck`** — ทุกบรรทัดต้องขึ้น ✔
6. **Deploy → New deployment → Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**  (ต้องเป็นแบบนี้ เพราะนักศึกษา/เว็บภายนอกต้องเรียกได้ — สิทธิ์จริงตรวจในโค้ดด้วย token)
   - คัดลอก **Web app URL** (ลงท้าย `/exec`)
7. ไฟล์ฐานข้อมูล (Google Sheet ชื่อ `HBT_Core — HBT Teaching System`) ถูกสร้างในไดรฟ์ของคุณ — **อย่าแก้ข้อมูลตรงๆ ในชีต** ให้ผ่านหน้าเว็บ

> แก้โค้ดภายหลัง: Deploy → **Manage deployments → ✏️ → Version: New version → Deploy** (URL เดิม ไม่เปลี่ยน)  
> ถ้าไม่ทำ เว็บจะยังเรียกโค้ดเวอร์ชันเก่า

### B2) ติดตั้ง Exam API (Apps Script ตัวที่ 2 — ข้ามได้ถ้ายังไม่ใช้ระบบสอบ)

1. ที่โปรเจกต์ **Core**: เลือกฟังก์ชัน **`setupShowSecret`** → Run → คัดลอกค่า `SEC_TOKEN` จาก Execution log (ความลับ — อย่าส่งต่อ/อย่าโพสต์)
2. <https://script.google.com> → New project ใหม่ (ชื่อ เช่น `HBT Exam`) → ติ๊ก Show manifest → สร้างไฟล์ตามโฟลเดอร์ `exam/` ให้ครบ: `Config, Util, Db, Auth, CoreLink, Audit, Quiz, Rounds, Runner, Report, Sync, Purge, Router, Setup` (.gs) + แทนที่ `appsscript.json` (มี Drive advanced service เช่นเดียวกับ Core — ใช้ลบรูปข้อสอบถาวร)
3. เปิด `Setup.gs` ของ Exam แก้ `SETUP`:
   ```js
   CORE_URL: 'https://script.google.com/macros/s/AKfy.../exec',   // URL ของ Core (ลงท้าย /exec)
   SEC_TOKEN: 'ค่าที่คัดลอกจากข้อ 1',
   SPREADSHEET_ID: ''                                              // เว้นว่าง = สร้างชีตใหม่ให้
   ```
4. เลือก **`setupExam`** → Run → อนุญาตสิทธิ์ (Sheets, Drive, เรียกบริการภายนอก, ตัวจับเวลา) → **ลบค่า `SEC_TOKEN` ออกจาก `SETUP` ทันที** (ค่าถูกเก็บใน Script Properties แล้ว) แล้วรัน **`setupCheck`** — ทุกบรรทัดต้องขึ้น ✔ (รวม “เรียก Core ได้ (secret ตรงกัน)” และ “มีตัวจับเวลา tick_”)
5. **Deploy → New deployment → Web app** — Execute as: **Me**, Who has access: **Anyone** → คัดลอก URL `/exec`
6. กลับไปที่ **Core**: ใส่ URL นั้นที่ `SETUP.EXAM_URL` ใน `Setup.gs` → รัน `setupCore` ซ้ำ → **Deploy → New version**  
   (Core ต้องรู้ URL ของ Exam เพื่อสั่งลบข้อมูลสอบตอนลบนักศึกษา)
7. ใส่ URL เดียวกันใน `web/assets/config.js` ที่ `EXAM_URL` แล้วอัปโหลดเว็บใหม่
8. ให้อาจารย์มีสิทธิ์ระบบ `exam` ที่หน้า *ผู้ใช้และสิทธิ์*

> ถ้าหมุน secret ที่ Core (`setupRotateSecret`) ต้องคัดลอกค่าใหม่ไปใส่ที่ Exam (`SETUP.SEC_TOKEN`) แล้วรัน `setupExam` ซ้ำ — ไม่งั้น Exam เรียก Core ไม่ผ่าน (นักศึกษาจะขึ้น "Core ไม่ตอบสนอง")  
> การเริ่มทำข้อสอบต้องมี Core ทำงานอยู่ด้วย (ตรวจสิทธิ์/รายชื่อ — แคช 60–120 วินาที) แต่คนที่เริ่มไปแล้วทำต่อได้

### C) ตั้งค่าและขึ้นเว็บ

1. แก้ `web/assets/config.js`:
   ```js
   window.HBT_CONFIG = {
     GOOGLE_CLIENT_ID: '1234-abc.apps.googleusercontent.com',
     CORE_URL: 'https://script.google.com/macros/s/AKfy.../exec',
     EXAM_URL: 'https://script.google.com/macros/s/AKfy.../exec'   // Exam API (เว้นว่าง = ยังไม่ใช้ระบบสอบ)
   };
   ```
2. อัปโหลดทั้งโฟลเดอร์ `web/` เป็นรากของ GitHub Pages (Settings → Pages → Deploy from branch)  
   ถ้าเว็บอยู่ที่ `https://user.github.io/hbt/` ให้แน่ใจว่า origin `https://user.github.io` อยู่ใน Authorized JavaScript origins แล้ว
3. เปิด `…/t/login.html` → ลงชื่อเข้าใช้ด้วยบัญชีผู้ดูแลคนแรก
4. ไป **ตั้งค่าระบบ** → เพิ่มภาคเรียนแรก · ไป **ผู้ใช้และสิทธิ์** → เพิ่มอีเมลอาจารย์

## ความปลอดภัย — อะไรตรวจที่ไหน

| เรื่อง | ที่ตรวจ | หมายเหตุ |
|---|---|---|
| โดเมนอีเมล | **server** (`Auth.verifyGoogle`) | เทียบทั้ง `hd` ของ token และท้ายอีเมล · หน้าเว็บไม่ได้เป็นตัวตัดสิน |
| ตัวตนผู้ใช้ | server: token HMAC + อ่านสิทธิ์จากชีต Users | แก้ผ่านหน้าเว็บมีผลทันที · ถ้าไปแก้ตรงในชีตมีผลภายใน ~60 วินาที (แคช) |
| ป้องกันปลอม token | ลายเซ็น `SEC_TOKEN` (เก็บใน Script Properties เท่านั้น) | รั่วสงสัย → รัน `setupRotateSecret` ทุกคนต้องล็อกอินใหม่ |
| PIN นักศึกษา | server (`Pin.gs`) | แฮช SHA-256 + salt ต่อคน + pepper `SEC_PIN` · กันเดาด้วยการล็อกต่อรหัสนักศึกษา · หน้า PIN ไม่บอกว่ารหัสนักศึกษาไหนมี/ไม่มีในระบบเกินที่ต้องเลือกจากรายการ |
| สิทธิ์ข้อมูลรายวิชา | server (`Courses.require`) | ทุก API ของรายวิชา/นักศึกษา/คะแนนตรวจ "เจ้าของวิชาหรือ admin" ทุกครั้ง |
| token นักศึกษา (ส่งงาน) | server (`Auth.requireStudent`) | ชนิด `s` แยกจาก token อาจารย์ (สลับกันใช้ไม่ได้) · ผูกกับวิชา+รหัสนักศึกษา · อายุ 2 ชม. · ทุกคำสั่งตรวจว่านักศึกษายังอยู่ในวิชา · ทุกคำสั่งเช็คว่างาน/ไฟล์เป็นของวิชา/ของตัวเอง |
| ไฟล์งาน | server (`Assignments.stuUpload`) | ตรวจนามสกุล + ไบต์หัวไฟล์ + ขนาด + จำนวน ก่อนขึ้น Drive · เก็บใน Drive เจ้าของ Web App ไม่แชร์สาธารณะ · อาจารย์โหลดผ่าน `asg.fileGet` (ตรวจสิทธิ์เจ้าของวิชา) · รหัสไฟล์/โฟลเดอร์ Drive ไม่ถูกส่งให้นักศึกษา |
| token สอบ (Exam) | server (`Auth.gs` ของ Exam) | ใช้ `SEC_TOKEN` ตัวเดียวกับ Core แต่ **แยกชนิด**: `s` นักศึกษา (Core) · `a` การทำข้อสอบ 1 ครั้ง (Exam ออก ผูกกับ attempt+รอบ+คน อายุ = ถึงเวลาปิดรอบ + 30 นาที) · `x` บริการ (Core↔Exam 5 นาที) — สลับกันใช้ไม่ได้ |
| เฉลยข้อสอบ | server (`Runner`) | โหมดสอบไม่ส่งเฉลย/ตัวชี้ข้อถูกไปหน้าเว็บเลย · คำตอบถูกตรวจที่ server · เวลาต่อข้อตรวจที่ server · โหมดฝึกทำเปิดเฉลยหลังตอบแล้วเท่านั้น |
| ค่าที่เสี่ยงล็อกตัวเอง | Client ID / โดเมน / secret **แก้ผ่านเว็บไม่ได้** | แก้ได้เฉพาะใน Apps Script (`Setup.gs`) |
| กู้ระบบเมื่อไม่มี admin | `setupAddFirstAdmin` (รันใน Apps Script) | ต้องเป็นเจ้าของสคริปต์ |

ข้อจำกัดที่ควรรู้:
- **รายชื่อนักศึกษาในรายวิชาปัจจุบันเปิดให้หน้า PIN เห็นโดยไม่ล็อกอิน** (เลือกอาจารย์ → วิชา → ชื่อ เพื่อความสะดวกบนมือถือ) แต่แสดงเฉพาะรหัสกับชื่อ ไม่มีอีเมลอาจารย์/สถานะ PIN · ถ้ากังวลเรื่องความเป็นส่วนตัว ขั้นถัดไปเพิ่ม "รหัสเข้าห้อง" ที่อาจารย์แจกได้
- ใครรู้รหัสนักศึกษาสามารถกด PIN ผิดจนล็อกคนนั้นชั่วคราวได้ (ล็อกตามรหัสนักศึกษา) — แลกกับการกันเดา PIN
- ออกจากระบบ = ทิ้ง token ที่เบราว์เซอร์ (token ไม่ได้ถูกเพิกถอนที่ server จนกว่าจะหมดอายุ 8 ชม.) — ถ้าต้องตัดทันทีให้ปิดบัญชีผู้ใช้ หรือ `setupRotateSecret`
- เซสชันเก็บใน `sessionStorage` (ต่อแท็บ) — เปิดแท็บใหม่ต้องล็อกอินใหม่ด้วยปุ่ม Google 1 ครั้ง
- **ไฟล์ที่ลบ/แทนที่/ลบงาน ไปอยู่ในถังขยะ Drive ซึ่งยังนับโควตาไดรฟ์** จนกว่าจะล้างถัง — **ตอนลบข้อมูลสิ้นภาคเรียน (ขั้น 6) ไฟล์ถูกลบถาวรด้วย Drive advanced service** (ถ้าใช้ไม่ได้ลดเป็นถังขยะและแจ้งในหน้าลบ)
- การอัปโหลดผ่าน Web App จำกัดขนาดคำขอราว 9 MB (ตั้งเพดานไฟล์ไว้ 6 MB) — ไฟล์ใหญ่กว่านั้นให้แปะลิงก์ · นักศึกษาที่เครือข่ายหลุดกลางอัปโหลด หน้าเว็บลองใหม่เอง (ไฟล์ซ้ำภายใน 60 วินาทีถูกกันไว้)
- ใครรู้ชื่อ+PIN ของนักศึกษาส่งงานแทนได้ (PIN คือตัวตนเดียวของนักศึกษา) — กันเดาด้วยการล็อกเหมือนเช็คชื่อ
- **ขั้น 5 — Exam ต้องพึ่ง Core**: ถ้า Core ล่ม นักศึกษา **เริ่ม/ทำต่อจากเดิม** และอาจารย์ใช้หน้าจัดการไม่ได้ (ข้อมูลสิทธิ์/รายชื่อมีแคช 60–120 วินาที) · คนที่เข้าทำอยู่แล้ว (มี token การทำข้อสอบ) ตอบและส่งต่อได้ — คะแนนจะส่งเข้า Core ให้เองเมื่อ Core กลับมา · อาจารย์ปรับสิทธิ์แล้วมีผลที่ Exam ช้าสุด ~60 วินาที · เปลี่ยนภาคเรียนปัจจุบันแล้ว Exam เห็นภายใน ~5 นาที
- **รูปในข้อสอบเป็นลิงก์ Drive แบบสาธารณะ** (ใครมีลิงก์เห็นได้ — หน้าข้อสอบต้องแสดงรูปให้นักศึกษาโดยไม่ล็อกอิน) อย่าใส่ข้อมูลที่ไม่ต้องการให้เปิดเผยในรูป
- ลบนักศึกษา/นำเข้าแบบแทนที่ **ถูกปฏิเสธ (`E_EXAM_DOWN`) เมื่อ Exam ตั้ง URL ไว้แต่ติดต่อไม่ได้** — ไม่ลบทั้งสองฝั่ง จะได้ไม่เหลือข้อมูลสอบค้าง (ลองใหม่เมื่อ Exam กลับมา)
- ความเปลี่ยนแปลงจาก EEOS เดิม: นับครั้งที่ทำที่หมดเวลาโดยไม่ได้ทำต่อ (กันช่องว่างเพิ่มครั้งทำ) · เลือกข้อถูกด้วยการติ๊ก (ไม่ใช่ “ตัวเลือกแรกคือข้อถูก”) · ข้อที่หมดเวลาแล้วนับคำตอบที่เลือกไว้ · เตือนออกนอกจอเฉพาะรอบที่เปิดล็อกแท็บ · **ตัดออก**: สลับภาษาอังกฤษ, แดชบอร์ดระดับรายวิชา, หน้ารายละเอียดนักศึกษารายคน
- **ขั้น 6 — การลบเป็นถาวร**: ไม่มีถังขยะและกู้ไม่ได้ · มีเฉพาะ admin (ตรวจที่ server `auth:'admin'` + ต้องพิมพ์รหัสวิชา-กลุ่มที่ server ตรวจซ้ำ ไม่ใช่แค่หน้าเว็บ) · การเตือน “ยังไม่สำรอง” **เป็นคำเตือน ไม่ใช่การห้าม** — admin ยืนยันแล้วลบได้
- **ขั้น 6 — “สำรองครบ” เชื่อใจได้แค่ระดับหนึ่ง**: ระบบรู้ว่าอาจารย์กดให้ดาวน์โหลดครบทุกรายการ ไม่รู้ว่าไฟล์ถูกบันทึกลงเครื่องจริง (เบราว์เซอร์อาจบล็อกการดาวน์โหลดซ้ำ) · การแก้ข้อมูลฝั่งสอบออนไลน์ (ข้อสอบ/ผลสอบ) **ไม่ทำให้สถานะเป็น “มีแก้ไขหลังสำรอง”** · **รูปประกอบข้อสอบไม่อยู่ในชุดสำรอง** (ไฟล์ CSV ใช้ `[IMAGE]` แทน) และถูกลบถาวรตอนลบวิชา
- **ขั้น 6 — ระหว่างและหลังลบ**: วิชาที่ลบค้างอยู่เข้าไม่ได้ทันที (นักศึกษาก็เข้าไม่ได้) · ฝั่งสอบอาจารย์อาจยังเห็นวิชานั้นอีกไม่เกิน ~60 วินาที (แคชสิทธิ์) แต่ข้อมูลถูกลบแล้ว · ไฟล์ที่นักศึกษา/อาจารย์เคยดาวน์โหลดไปเองอยู่นอกการควบคุมของระบบ
- Apps Script จำกัดโควตา/เวลา: Core เรียกเบาๆ (อ่านผ่านแคช) แต่ยังไม่ได้ทดสอบโหลดจริงพร้อมกันหลายร้อยคน

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| หน้าเว็บบอก "ยังไม่ได้ตั้งค่าเว็บ" | `config.js` ยังว่าง `GOOGLE_CLIENT_ID` หรือ `CORE_URL` |
| ปุ่ม Google ไม่ขึ้น / error `origin_mismatch` | origin ของเว็บไม่อยู่ใน Authorized JavaScript origins (ต้องตรงเป๊ะ รวม https และไม่มี path) — รอ Google อัปเดตได้ถึงไม่กี่นาที |
| ล็อกอินแล้วขึ้น "ระบบยังตั้งค่าไม่เสร็จ" (`E_NOT_SETUP`) | ยังไม่ได้รัน `setupCore` หรือ Client ID ว่าง |
| "ยืนยันตัวตนกับ Google ไม่สำเร็จ" ทุกครั้ง | Client ID ใน `Setup.gs`/`Setup.local.gs` กับ `config.js` ไม่ตรงกัน (รัน `setupCore` ใหม่หลังแก้) |
| เชื่อมต่อเซิร์ฟเวอร์ไม่ได้ / CORS error | Web app ต้อง deploy เป็น **Anyone** (ไม่ใช่ "Only myself"/"Anyone with Google account") และ `CORE_URL` ต้องลงท้าย `/exec` |
| แก้โค้ดแล้วไม่เปลี่ยน | ต้อง Deploy เป็น **New version** (ดูด้านบน) |
| `Authorization is required` | รัน `setupCore` ใน editor อีกครั้งเพื่ออนุญาตสิทธิ์ แล้ว deploy เวอร์ชันใหม่ |

### โฟลเดอร์ `exam/` (Exam API)

| ไฟล์ | หน้าที่ |
|---|---|
| `Config.gs` / `Util.gs` / `Db.gs` | ค่าคงที่ · ซองคำตอบ/error/lock/แคช · ชีต + `SCHEMA` (ชีตของ Exam แยกจาก Core) |

| `Quiz.gs` | ชุดข้อสอบ · ข้อสอบ · รูป (Drive) · นำเข้า–ส่งออก CSV |
| `Rounds.gs` | รอบสอบ · ลิงก์ · เปิด/ปิด · ติดตามสด |
